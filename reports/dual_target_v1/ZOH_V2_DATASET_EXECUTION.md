## 新版实现

新增独立 `zoh_dataset*` 模块；不修改已批准的 ZOH gate 源码、旧合同或旧数据。所有执行模块在队列创建时绑定 hash，每条运行前重验源码、gate 批准报告和固定计划。

- 32 个任务全部新采：train 16、validation 8、test 8。train 采用原四组几何；val/test 为已确认的新坐标，组/trajectory/派生签名划分检查通过。箱子在一条轨迹内静止。
- 200 Hz 物理、50 Hz 低层、5 Hz 真正专家命令更新与 ZOH，共享约束与 gate 一致，默认 chunk 5 / execute 1。5 Hz 高层日志是每个新决策点真实生成，不是对旧数据抽帧。
- 首次停车评分成功后不立即退出。继续正常专家控制与接触/跌倒等检查，直到尾部有六个完整、真实停稳且原始/施加命令均为零的高层段；严格保留 30 秒时限。
- 原评分器会锁存成功，因此新采集循环显式保持后续失败优先级；成功后的停稳条件丢失则保留该次失败并停止批次，不将原成功沿用为采集通过。
- `high_level_segments.jsonl` 记录每段真实低层步数、真实持续时间及完整标记。转换只接纳 10 个低层步、实际持续时间约 0.2 秒的动作段；不足段不得伪造执行、不得跨 episode 补齐。新成功演示要求结尾无不足段。
- 每个高层 RGB 解码审计目标颜色像素数、目标包围框、面积比例、是否触边；颜色像素少于 100 时阻止该批次继续，起点要求两色均可见。距边缘 ≤5 px 或目标面积 <1% 记为预警，保留原帧和轨迹，不因靠边静默删除。后续主代理需重点查看全部有边缘预警的轨迹。
- train 与 validation 独立 LeRobot 目录，test 轨迹仅存 `test_audit/`，不导出 test LeRobot 数据。真值与可见性标记只在审计 sidecar，不进入 learner 特征。
- CPU 转换为 5 Hz / chunk 5，query offset [0,0.2,0.4,0.6,0.8]；末尾 action padding 仅在查询时存在，并按 mask 忽略，不增加真实训练帧。
- normalizer 只由 train 创建；vy 固定零且不计损失。episode 等权、有放回 sampler，报告起步、近零、chunk 近零与 padding 暴露。转换内以真实 loader 对每条起点、中段、停车与尾部边界回查 RGB/状态/动作/task/mask。
