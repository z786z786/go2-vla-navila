## 2. Leakage 判定：无泄漏

`annotations.json` 记录格式（实测）：

```json
{"video_id":"914-23",
 "q":"Turn and walk away from the bathroom into the bedroom area. ...",
 "a":"The next action is move forward 75 cm.",
 "frames":["914/frame_0.jpg","914/frame_1.jpg", ...]}
```

**无 `scene_id` 字段**，scene 身份必须 join 恢复。两个陷阱：

1. **不能按 `video_id` / `episode_id` join**：数字 id 跨 split 碰撞。实测 9471 个前缀里 train 命中 9471、val_unseen 也命中 1588，纯 id 无法区分。
2. 正确做法是按 **instruction 原文** join（归一化 `' '.join(s.split()).strip().lower()`），指令文本实质唯一。

**前置事实（主代理实测）**：评测用的 11 个 scene **恰好就是 R2R `val_unseen` 的 11 个 scene，集合相等**。
`train` 61 / `val_seen` 53 / `test` 18 与之交集均为空。
因此 leakage 问题等价于单一问题：**NaVILA 的 R2R 数据里有没有 `val_unseen` 的 episode？**

实测（前 23 MB，26,429 条记录、9,469 条不同指令）：

| split | 匹配 | 覆盖 |
|---|---|---|
| **train** | **9,469** | **100.0%** |
| val_seen | 0 | 0% |
| val_unseen | 2 | 0%（该 2 条同时存在于 train，属跨 split 重复字符串，非 val_unseen 独有） |
| test | 1 | 同上 |
| 无法解释 | **0** | — |

`val_unseen − train = 0`；train 匹配蕴含 scene 恰好 **61 个 = R2R train 全集**；**与 eval11 交集 `[]`**。

**判定：NO-LEAKAGE。** 用户于 2026-09-12 确认此结论并指示停止进一步核查，
全量复核（`R2R_annotations.json` 已下至 125 MB / 317 MB，可 `curl -C -` 续传）**按用户指示终止**。
方法学声明保留：部分样本只能证明 leakage 不能证伪，本判定的样本覆盖为 8.3%，
其成立还依赖「NaVILA 不用 val_unseen 训练」这一与常规做法一致的结构性论证。

## 3. 动作语义（本报告最具决策价值的一节）

源码 `third_party/NaVILA-Bench/isaaclab_exts/omni.isaac.vlnce/omni/isaac/vlnce/utils/eval_utils.py:57-85`
的 `get_vel_command()` 原文：

```python
turn left  45/30/15  ->  [0, 0, +np.pi/6], 1.5 / 1.0 / 0.5 s
turn right 45/30/15  ->  [0, 0, -np.pi/6], 1.5 / 1.0 / 0.5 s
forward 75/50/25 cm  ->  [0.5, 0, 0],      1.5 / 1.0 / 0.5 s
stop                 ->  [0, 0, 0],        0.0 s
解析失败兜底          ->  [0.5, 0, 0],      0.5 s
```

执行路径：prompt（`scripts/vlm_server.py:122-134`）→ `get_vel_command()` → (速度, 时长)
→ `navila_eval.py:330-333` 按 `duration / (sim.dt × decimation)` 换算步数 → `wrappers.py:201-245` 下发
→ 低层策略。**是速度指令 + 时长，不是位姿传送。**

由此得出三条与本项目契约冲突的事实：

| # | 事实 | 与 §3.2 契约的冲突 |
|---|---|---|
| 1 | NaVILA `wz = π/6 = 0.523599 rad/s` | **超出 `wz ∈ [-0.5, 0.5]` 上限 4.72%**。每一次转向都越界 |
| 2 | NaVILA `vx` **恒为 0.5 m/s**（单一常数，非范围） | 契约为 `[0, 0.5]`；而 Go2 expert 实测 vx 最大 **0.349996**。**两源 vx 分布几乎不相交** |
| 3 | 解析失败兜底为「前进 25 cm」 | §P6 冻结为「零速度意图 + limiter 制动」。**行为相反**，移植 parser 必须改掉 |

**动作空间基数**：NaVILA 的动作集在速度维度上只有 **3 个取值**——`vx ∈ {0, 0.5}`、`wz ∈ {0, ±π/6}`，
变化全部由**时长**承载（0.5 / 1.0 / 1.5 s）。

**5 Hz 固定 tick 的量化代价**（主代理独立复算）：

| 宏动作 | NaVILA 精确值 | tick 数 | floor | ceil |
|---|---|---|---|---|
| turn 15° | 15.0° | 2.5 | 12.00°（−3.00°） | 18.00°（+3.00°） |
| turn 30° | 30.0° | 5.0 | **30.00°（0）** | 同左 |
| turn 45° | 45.0° | 7.5 | 42.00°（−3.00°） | 48.00°（+3.00°） |
| forward 25 cm | 0.25 m | 2.5 | 0.20 m（−0.05 m） | 0.30 m（+0.05 m） |
| forward 50 cm | 0.50 m | 5.0 | **0.50 m（0）** | 同左 |
| forward 75 cm | 0.75 m | 7.5 | 0.70 m（−0.05 m） | 0.80 m（+0.05 m） |

NaVILA 的宏动作在**时长制**下精确可实现；残差**完全由本项目「固定 5 Hz、取消 duration」的选择引入**
（§0 修订 #1）。八个宏动作中 **6 个落在半个 tick 上**。§7 风险表把 duration 列为「接受的已知局限」，
本节为其补上定量代价：**±3° 或 ±0.05 m**。

## 5. Embodiment gap

视角/高度差：**UNVERIFIABLE**，未伪造对比图或差距数值。

但 §3 给出了一个比视角差距更硬、且已量化的 gap：**动作分布 gap**。
NaVILA 是 point-agent 的 3 值速度 + 时长控制；Go2 expert 是连续速度、vx ≤ 0.35、wz applied 夹在 ±0.5。
这正是 §21 第四大失败点「训练数据由 point-agent 产生，测试却用 Go2」的具体形态，
且它**不依赖**未取到的 NaVILA 帧即可成立。

## 6. 裁决：推荐 **方案 B 打头 + 保留 NaVILA 数据作为 P8 期权**

### 推荐

1. **P4 首批 50 条走方案 B（纯 Go2 rollout）**，E1 与 E2 **训练于同一批数据**。
   语言标签按 §P4 既定方案，由**版本化分段器从连续序列生成**（保存起止 tick、积分距离/角度、量化残差）。
2. **NaVILA 公开数据现在就归档备用**，不进 P4 关键路径。已确认无 leakage、可获取，
   `R2R_annotations.json` 已下 125 MB / 317 MB（可续传），全量 R2R ≈ 20 GB，落 `/mnt`（余 1.8 TB）。
   它的用途是 **P8 的一条预训练消融**，在平台跑通之后做。
3. **条件升级路径（方案 D，非当前计划）**：若 P6 证明 LLaDA-V 在 50–500 条 Go2 数据上无法收敛，
   则升级为「NaVILA 预训练 + Go2 微调」，且**必须对 E1 与 E2 对称施加**，不得只给一条线。

### 否决 A（两条线都用 NaVILA 预训练 + Go2 适配）作为当前主方案

**主因：它会让主研究问题失去意义。** NaVILA 的速度维度只有 3 个取值（`vx ∈ {0, 0.5}`、`wz ∈ {0, ±π/6}`），
变化全在时长上。用它当 E1 的主监督，SmolVLA 的连续动作空间会**塌缩成 3 档离散**——
E1 变成"穿着连续外衣的离散策略"。而 §1 立的主研究问题是 **continuous vs language 动作表示对比**；
两边都成了离散，这个对比就不成立。

次因：
- vx 恒 0.5 与 Go2 expert ≤ 0.35 **几乎不重叠**，适配阶段要跨越的不是小 gap 而是几乎整个分布。
- wz = π/6 每次转向越契约界，重放必然触发 clipping，训练目标与执行结果系统性不一致。
- §21 第四大失败点（point-agent 训练 / Go2 测试）在此方案下直接兑现，而 embodiment gap 的视觉侧还是 UNVERIFIABLE。
- §21 第五点「平台没跑通就烧 GPU」已在 M7 发生过四轮；在平台从未闭环前先加一个预训练阶段，正是重犯。

### 否决 C（只给 language 线用）作为当前主方案

**这是主代理上一轮的倾向，现更正。** C 的问题是：E1 训练于 Go2 rollout、E2 训练于 31 万条公开数据，
**两条线的训练数据在来源、本体、场景覆盖和数量级上全部不同**。
§P8 允许 E1/E2 作为系统对比并要求披露差异，但 C 把差异放大到**训练数据量级相差约三个数量级**，
此时"哪个系统更好"几乎只反映"谁的数据多"，与动作表示无关。
而 §1 的项目目标是建成**能公平比较**不同策略的平台——C 用平台的核心目的去换单条线的性能，代价不对等。

C 的唯一合理形态是作为 D 的降级版，即在**已经确认 E2 无法在 Go2 数据上收敛**之后的不得已选择，
且届时须在主表中显著标注训练数据不对称。**不作为首选。**

### 附带裁决：vx 上界

选定方案 B 后，P1 应把 §3.2 的 `vx` 上界**收到 0.35 m/s**（而非 0.5），理由是行为克隆下
`(0.35, 0.5]` 无任何监督数据，保留该区间等于允许模型在无监督区自由输出——
与 §0 修订 #2 收紧 wz 的理由完全同构。该值是配置项，待数据覆盖后可再放开，须在 `action.yaml` 注明依据。
若日后采用方案 D，NaVILA 的 vx=0.5 与 wz=π/6 须在 adapter 层显式夹到契约内并记录夹取率。

## 7. 成本估算（实测基线，替代 §P4 已撤销的固定预算）

§P4 v2 撤销了「50 条约 4 小时 / 1.1 GB、200 条约 15 小时 / 4.4 GB」的预算，要求用实测时长分布重估。
本节用 **all61 批次 60 条真实 episode** 与**本会话实测下载吞吐**重建，取代 ep1 单条外推。

### 7.1 方案 B 单位成本（实测，n=60）

| 量 | 实测值 |
|---|---|
| 每条**成功** episode 墙钟（含失败开销） | **7.36 min** |
| 每条成功 episode 字节（含失败开销） | **46.9 MB** |
| 成功率 | **56.7%**（34/60） |
| 每条 episode 中位 action 记录数 | 210 |
| 实时率（中位） | 0.24（文档基线 0.203，实测略优） |
| 分状态墙钟中位 | success 2.73 min／timeout **8.23 min**／warmup failed ≈0／env termination 0.39 min |

**timeout 是最贵的失败形态**：18/60 条撞上 `--max-seconds 120` 上限，各耗 8.23 min 中位墙钟、
产出 46.8 MB 不可用数据。提高上限会线性放大这项成本。

### 7.2 方案 B 分级门禁成本

| 级别 | 墙钟（GPU 独占，串行） | 磁盘 | step 样本数 |
|---|---|---|---|
| 50 条成功 | **6.1 h**（0.26 d） | 2.34 GB | ~10,500 |
| 200 条成功 | **24.5 h**（1.02 d） | 9.37 GB | ~42,000 |
| 500 条成功 | **61.3 h**（2.56 d） | 23.43 GB | ~105,000 |

与撤销的旧预算对比：50 条实测 **6.1 h / 2.34 GB**，旧估 4 h / 1.1 GB ——
旧估在时间上乐观约 35%、在体积上乐观约 53%。撤销是正确的。

**未计入的风险**：上述以 56.7% **成功率**计，而 all61 全 60 条 `training_eligible=false`，
**可训练率至今未测**。若可训练率显著低于成功率，B 的成本按比例放大。
另需计入：3090 为共享卡，官方 1077 队列曾因 `GPU free below 2048 MiB` 被准入门禁中止；
61.3 h 独占是实打实的排期风险。

### 7.3 方案 A 成本（实测吞吐）

下载量 **20.02 GB** = `R2R/annotations.json` 0.32 GB + `R2R/train.tar.gz` 19.70 GB
（`content-length` 实测 19,703,787,520，已核）。

本会话 3 次 20 MB 定时 range 取样：**1.71 / 0.49 / 0.45 MB/s**（中位 0.49、均值 0.88）。

| 吞吐 | 纯传输 | 计 30% 重连开销 |
|---|---|---|
| 最好 1.71 MB/s | 3.3 h | **4.6 h** |
| 均值 0.88 MB/s | 6.3 h | **9.0 h** |
| 中位 0.49 MB/s | 11.3 h | **16.2 h** |

- **磁盘**：20.0 GB 压缩态；JPEG 在 gzip 下几乎不压缩，解包后再约 20 GB → 峰值约 **40 GB**。`/mnt` 余 1.8 TB，无压力。
- **GPU：0 小时。** 可断点续传（`curl -C -`）、可无人值守过夜、可与其他工作并行。
- **样本量**：约 **363,000** 条 step 级监督（由 23 MB / 26,429 条按文件大小外推），覆盖 R2R train 10,819 episodes / 61 scenes。

### 7.4 单位经济性对比

| | 每墙钟小时 step 样本 | GPU 占用 |
|---|---|---|
| **A** | **~40,300** | 无 |
| **B** | **~1,710** | 独占 |

**A 的样本获取效率约为 B 的 24 倍，且不占 GPU。**

要用 B 凑到 A 的样本量，需约 **1,731 条成功 episode**
= **8.8 天 GPU 独占、81 GB**，且按 56.7% 成功率需约 **3,054 次尝试**。
**两者在规模上不可互替。**

### 7.5 成本对裁决的影响

**成本明确偏向 A。** §6 推荐 B 是**明知成本劣势而选择的**：
用约 24 倍的样本获取效率、以及 6.1 h GPU 独占（对 4.6–16.2 h 无 GPU 下载）换取两件事——

1. E1 拥有**真实连续速度监督**，而非由 adapter 从 3 档离散值合成的目标；
2. E1 与 E2 训练于**同一批数据**，使主对比可解释。

这笔溢价的实际规模并不大：**首批 50 条只要 6.1 h GPU 独占 + 2.34 GB**，
在 P4 分级门禁下也只到这一级。真正的成本悬崖在 500 条（61.3 h）及以上，
而那一级的必要性由 P4 的 SR 曲线决定，不是现在要付的账。

因此结论不变：**B 打头**；A 的 20 GB 作为 P8 预训练消融的期权，
其下载可在**任何时候后台无 GPU 进行**，不与主线争资源——这是它成本结构上的最大优势，
也正是它适合当期权而非关键路径的原因。
